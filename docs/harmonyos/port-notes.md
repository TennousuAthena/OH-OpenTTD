# HarmonyOS 移植与性能记录

## 鼠标滚轮方向修复（2026-10-04）

在 `15.3-harmonyos.1` 上修复鼠标滚轮上下方向都被识别为向上的问题。
普通滚轮轴事件没有捏合缩放，缩放值为 `0`；旧判断将其当成向内捏合，
覆盖了垂直和水平滚动增量，并使空轴事件也产生滚轮输入。
现在仅对有限且大于 `0` 的缩放值进行捏合处理，其余事件保留滚动方向；
无滚动增量的事件不再产生虚假滚轮输入。

新增 `mouse-wheel-axis` 回归用例，覆盖上下和水平滚动、空事件及无效缩放值。
修复前用例失败；修复后真实输入桥接的 5 组用例、11 项队列测试及输入规范的
13 组用例全部通过。DevEco Studio 26 / API 26 双 ABI 签名构建成功，
产物核验确认 `arm64-v8a` 与 `x86_64` 均使用有效的 `-O2 -g`，并且
打包库与调试符号 Build ID 匹配。既有性能优化和输入队列处理保留。

修复包已安装到 HarmonyOS 7 / API 26 MateBook 真机。通过原生 `uinput`
鼠标事件，确认垂直轴 `+1` 缩小地图、`-1` 放大地图，二者的捏合值均为 `0`。
AI 列表向下滚动后，反向滚动恢复“人类玩家”首行和顶部滚动条位置。
本轮暂停场景的 EGL 提交率保持约 60 次/秒；它不等同于新的整套性能评测。
测试完成后已恢复 `driver=1` 普通日志级别，并重新载入基线存档，恢复原始
视角、1952-05-09 日期、GBP 88,447 资金和暂停状态。
本地签名包、构建清单和验证记录保存在 `build/harmonyos/wheel-fix/`；
编译日志为 `build/harmonyos/deveco-api26-wheel-build.log`。

## 鸿蒙移植与性能优化（2026-10-03）

本仓库已将 OpenTTD 移植到 HarmonyOS，并完成一轮针对低帧率、鼠标积压和音乐线程阻塞的优化。优化诊断包已安装到 HUAWEI MateBook Pro 真机；当前基线存档在原生分辨率下达到约 60 次画面呈现/秒，保留原版玩法、素材、软件光标和存档格式。

### 已完成的改动

- **优化构建**：游戏核心和原生桥接统一使用有效的 `-O2 -g`，Debug 包也开启优化，同时保留诊断符号。高频调试日志默认关闭，性能计数通过 `--perf` 单独启用。
- **GPU 显示路径**：优先创建 GLES3 上下文，保留 GLES2 回退。32 位像素直接上传，由着色器调整颜色通道；GLES3 使用行跨度上传，GLES2 使用可复用的按行复制缓冲区，去掉原先逐像素转换和每帧临时分配。
- **调色板动画与上传**：接入上游 `40bpp-anim` 的动画缓冲区，将调色板和颜色动画交给 GPU，并兼容 8 位画面。使用最多 16 个脏区域，减少局部变化引起的整屏上传；修复动画光标备份在奇数宽度下的非对齐访问。
- **鼠标与输入**：队列一次交换为本地批次，释放队列锁后处理。仅合并连续、没有按钮按下且未固定滚屏的鼠标移动；保留点击、拖拽、释放、滚轮、键盘、触摸、IME 和焦点事件的顺序。
- **帧率与生命周期**：完善垂直同步，避免交换缓冲等待与定时限帧重复等待。EGL 操作仍在渲染线程，支持窗口缩放、Surface 重建及后台恢复。
- **音频与测量**：音乐播放状态查询改为原子快照，合成器控制仍保持同步。增加按秒汇总的输入排队、绘制、纹理上传、缓冲交换、音频及锁等待统计，并提供日志汇总和二进制核验脚本。

GPU 加速覆盖画面上传、颜色处理和调色板动画；游戏模拟与部分世界绘制仍由 CPU 执行。

### 真机结果与验证范围

测试设备为 arm64 MateBook HAD-W32，GPU 为 **Maleoon 916**，报告支持 **OpenGL ES 3.2**。显示屏为 3120 × 2080，游戏 Surface 为 **3120 × 2010**。对比使用相同的 Dedston 存档、视角、窗口尺寸和音乐设置，排除启动与加载阶段。

| 指标 | 原 Debug 构建 | 优化诊断构建 |
| --- | --- | --- |
| 暂停场景游戏内绘制率（单次快照） | 35.07 FPS | 60.00 FPS |
| 运行场景 RenderService 缓冲区呈现速率 | 34.20 次/秒 | 60.00 次/秒 |
| 运行场景呈现间隔 p95 | 209.05 ms | 16.85 ms |
| 运行场景最大呈现间隔 | 266.78 ms | 17.46 ms |
| 鼠标移动测试中输入排队的窗口 p95 上界 | 未采集 | ≤ 16.5 ms |

RenderService 数据来自每次捕获的 384 条缓冲区呈现记录，描述应用 Surface 的呈现节奏；输入排队数据描述事件进入队列到处理的时间，并非鼠标到屏幕的完整延迟。游戏内绘制率、EGL 提交率和实际呈现速率分别记录，不混用这些指标。

优化前的 15 秒 CPU 采样中，`UploadTexture` 临时字节数组的构造和析构占约 **69.5% 的周期加权样本**；优化后该热点消失。完整数据、采样口径和复测步骤见 [性能记录](./performance.md)。

已完成的验证包括：

- 真机鼠标移动、拖拽、滚屏、音乐开关、窗口缩放、后台恢复，以及 GLES2 回退和 8 位画面检查。
- 实际 GLES2/GLES3 着色器与 CPU 颜色结果对比，光标备份、纹理上传、批量输入和性能计数测试，以及生命周期线程检查。
- **arm64-v8a、x86_64** 两个 ABI 的构建、有效优化参数、DWARF 符号和 HAP/引擎/符号 Build ID 核验。

目前仅 arm64 在真机运行。大型后期存档、长时间连续建造、更多交互式 VSync 切换和 x86_64 真机仍需复测；单个基线存档的结果不能代表全部地图。测试后已恢复原配置和暂停的基线存档，并另存测试结束时的存档备份。

### 构建与本地成果

先按照 [鸿蒙移植指南](./port-guide.md) 准备 API 26 SDK、Python 3、主机工具、运行依赖与素材。依赖构建需要预先缓存指南指定的 xz 和 FreeType 源码归档。从仓库根目录执行：

```bash
# 构建两种 ABI 的优化原生引擎，并开启性能计数
bash scripts/harmonyos/build-target.sh arm64-v8a Debug --perf
bash scripts/harmonyos/build-target.sh x86_64 Debug --perf

# 组织完整 HAP 打包流程
bash scripts/harmonyos/package.sh Debug --perf
```

正常构建省略 `--perf`，仍使用 `-O2 -g`。仅在需要未优化的 Debug 对照时使用 `--unoptimized-debug`；该选项不允许用于 Release。安装到设备需要有效的签名和调试配置，`package.sh` 收集的 HAP 为 unsigned；签名构建及产物核验命令见 [性能记录](./performance.md#build-and-verify)。

本次本地成果保存在 `build/harmonyos/performance/`，包括已安装的 `openttd-harmonyos-optimized-perf.hap`、`native-build-manifest.json`、符号、日志及截图。优化前后采样另保存在 `build/harmonyos/performance-baseline*` 和 `performance-after*` 目录。这些构建产物不随仓库克隆提供。`package.sh` 的源码归档来自已提交的 `HEAD`，不包含当前未提交修改。
