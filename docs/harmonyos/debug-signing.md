# Debug signing — OpenTTD HarmonyOS port

Short version: local debug HAPs are built **unsigned** (`assembleHap` succeeds and
produces `entry-default-unsigned.hap`). Deploying to a real device or building a
release app requires a signing configuration. This document records the exact,
reproducible signing setup. **No signing key material is ever committed to the
repository.**

## Key security rule

All key material is generated **outside** the repo, under an OS temp directory:

```
/tmp/openttd-ohos-debug-signing/
```

The `.gitignore` additionally ignores any stray copy of this pattern, so a key
can never be staged even by accident:

```
**/openttd-ohos-debug-signing/
openttd-ohos-debug-signing/
/tmp/openttd-ohos-debug-signing/
```

## 1. Generate the ephemeral debug keystore + certificate

Requires a JDK (`keytool`). Verified with Corretto 17:

```bash
KEYDIR=/tmp/openttd-ohos-debug-signing
mkdir -p "$KEYDIR"

java_home="$(/usr/libexec/java_home -v 17)"   # macOS; pick any JDK 17+
"$java_home/bin/keytool" -genkeypair \
  -alias openttd-debug \
  -keyalg EC -groupname secp256r1 \
  -storetype PKCS12 \
  -keystore "$KEYDIR/openttd-debug.p12" \
  -storepass openttd-debug -keypass openttd-debug \
  -dname "CN=OpenTTD Debug, OU=OpenTTD, O=OpenTTD, C=NL" \
  -validity 3650

"$java_home/bin/keytool" -exportcert \
  -alias openttd-debug \
  -keystore "$KEYDIR/openttd-debug.p12" \
  -storepass openttd-debug \
  -file "$KEYDIR/openttd-debug.cer"
```

Produces (not committed):

| File | Purpose |
|---|---|
| `openttd-debug.p12` | PKCS#12 keystore (store/key password: `openttd-debug`) |
| `openttd-debug.cer` | Self-signed certificate |

## 2. The HarmonyOS .p7b profile constraint

Importantly, a HarmonyOS signing **profile** (`.p7b`) cannot be self-generated by
`keytool` — it is issued by AppGallery Connect (AGC) for the exact
`bundleName` + certificate fingerprint. For real-device installs, obtain the
debug profile from AGC:

1. AGC console → your app → 签名证书 (Signing certificates)
2. Create a debug certificate matching the fingerprint of `openttd-debug.cer`
   (`keytool -printcert -file openttd-debug.cer` → SHA256 fingerprint)
3. Download the generated `profile.p7b` into `$KEYDIR/`

For pure assembly QA (the default here) an unsigned HAP is sufficient, so no
AGC dependency is required to run the scaffold tests.

## 3. Wiring into build-profile.json5 (only when a .p7b exists)

`harmonyos/build-profile.json5` currently ships with `signingConfigs: []` so
`assembleHap` stays green without secrets in the tree. When a profile is
available, fill the placeholder **without committing it** — the reference lives
in an ignored/generated file (or the values are injected at build time):

```json5
"signingConfigs": [
  {
    "name": "default",
    "type": "HarmonyOS",
    "material": {
      "certpath": "/tmp/openttd-ohos-debug-signing/openttd-debug.cer",
      "storePassword": "openttd-debug",
      "keyAlias": "openttd-debug",
      "keyPassword": "openttd-debug",
      "profile": "/tmp/openttd-ohos-debug-signing/profile.p7b",
      "signAlg": "SHA256withECDSA",
      "storeFile": "/tmp/openttd-ohos-debug-signing/openttd-debug.p12"
    }
  }
]
```

and reference it from the product:

```json5
"products": [{ "name": "default", "signingConfig": "default", ... }]
```

then rebuild with:

```bash
node /Applications/DevEco-Studio.app/Contents/tools/hvigor/bin/hvigorw.js \
  assembleHap --mode module -p product=default
```

## 4. Checking a signed/unsigned HAP

`test-hap-contents.sh` validates the assembled HAP structurally. To inspect
signature presence:

```bash
unzip -l entry/build/default/outputs/default/entry-default-unsigned.hap
```

Signed builds emit `entry-default-signed.hap` and the archive contains an
`EBBG` (Huawei signature) block.
